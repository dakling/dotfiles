Add a shim validation and auto-fix system with the latch pattern decided in CONTEXT.md.

**New state variables:**
- `claude-code-emacs-panes--shim-validated` — nil initially, set to t or 'fallback after first check
- `claude-code-emacs-panes--shim-path` — cached resolved path to the tmux shim after validation

**New function `claude-code-emacs-panes--find-shim`:**
Search for bin/tmux in this order:
1. `claude-code-emacs-panes--package-dir/bin/tmux` (primary — straight.el build dir)
2. `~/.config/emacs/.local/straight/repos/claude-code-emacs-panes/bin/tmux` (repos fallback)
3. `~/code/emacs-packages/claude-code-emacs-panes/bin/tmux` (dev source fallback)
Return the first path that exists, or nil.

**New function `claude-code-emacs-panes--validate-and-fix-shim`:**
Called once on first use (lazy — not at startup per CONTEXT.md decision).
1. If `claude-code-emacs-panes--shim-validated` is non-nil, return immediately (latch pattern — skip after first pass per CONTEXT.md)
2. Call `claude-code-emacs-panes--find-shim`
3. If found but not executable: `(set-file-modes path #o755)` and message "claude-code-emacs-panes: Fixed shim permissions at %s"
4. If not found at primary location but found at fallback: copy to primary `bin/` dir, chmod, message "claude-code-emacs-panes: Copied shim from %s"
5. If found: set `claude-code-emacs-panes--shim-validated` to t, cache path
6. If NOT found anywhere: set `claude-code-emacs-panes--shim-validated` to 'fallback, message warning "claude-code-emacs-panes: tmux shim not found, falling back to native tmux" (per CONTEXT.md: warn in *Messages*)

**Modify `claude-code-emacs-panes--inject-env`:**
At the start, call `claude-code-emacs-panes--validate-and-fix-shim`. If validated state is 'fallback, skip env injection entirely and call orig-fn without modifications (fall back to native tmux per CONTEXT.md decision). This implements the latch-into-fallback behavior.

**Modify `claude-code-emacs-panes--shim-dir`:**
Use `claude-code-emacs-panes--shim-path` if available (cached from validation), fall back to current behavior if not yet validated.

**Do NOT:**
- Check on Emacs startup (CONTEXT.md: lazy check on first spawn)
- Retry after failure (CONTEXT.md: latch into fallback)
- Add a dedicated log buffer (CONTEXT.md: deferred)

Fix the critical CORE-02 gap: new vterm panes created by `create-pane` don't inherit the injected env vars. Also verify CORE-03/CORE-04 compatibility.

**Fix `claude-code-emacs-panes-create-pane`:**
The function creates new vterm buffers for agent panes, but these buffers get fresh shells WITHOUT the env vars needed for nested agent spawning. Fix by injecting env vars into the new vterm buffer's environment.

Modify `create-pane` to accept an optional env-vars parameter (list of "KEY=VALUE" strings). When creating the vterm buffer:
1. Let-bind `vterm-environment` to append the provided env vars (or call `claude-code-emacs-panes--env-vars` to generate them if not provided)
2. The vterm-mode call will pick up `vterm-environment` and set them in the shell

Best-effort approach per CONTEXT.md: inject env vars if available, don't fail if some are missing.

**Update shim `split-window` and `new-window` handlers:**
Currently the shim calls `(claude-code-emacs-panes-create-pane)` without env vars. The shim already runs in a process that has all the env vars set. Pass them through to Emacs:
- In the shim, when calling `emacs_eval` for `create-pane`, pass the current `EMACS_PANES_SERVER` value so the elisp side can construct proper env vars for the new pane
- Add a new elisp function `claude-code-emacs-panes-create-pane-with-env` that takes the server name and constructs env vars using the cached shim path

Actually, simpler approach: Since the elisp side already has `claude-code-emacs-panes--env-vars` which generates the correct env list, just let-bind `vterm-environment` inside `create-pane` using that function. The shim doesn't need to pass env vars — the elisp side already knows them.

Specifically in `create-pane`:
```elisp
(let* ((extra (claude-code-emacs-panes--env-vars))
       (vterm-environment (append extra (when (boundp 'vterm-environment)
                                          vterm-environment))))
  ;; existing vterm-mode call happens inside this let
  )
```

This ensures every new pane gets PATH (with shim dir), TMUX, TMUX_PANE, CLAUDE_CODE_EMACS_PANES, and EMACS_PANES_SERVER in its environment.
