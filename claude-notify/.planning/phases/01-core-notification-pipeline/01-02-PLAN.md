**A. Create the shell script** at `~/code/emacs-packages/claude-notify/bin/claude-notify-hook.sh`:

```bash
#!/usr/bin/env bash
# claude-notify-hook.sh
# Bridge: Claude Code CLI Notification hook -> Emacs via emacsclient
# Reads JSON from stdin, passes to Emacs via server-eval-args-left (Emacs 30+)
# Called by Claude Code when a Notification event fires.
# MUST exit 0 always -- never block Claude Code.
set -euo pipefail

JSON=$(cat)

# Socket path is set by the install-hook command via environment variable
SOCKET="${CLAUDE_NOTIFY_EMACS_SOCKET:-server}"

emacsclient -s "$SOCKET" \
  --eval '(claude-notify--handle-hook (pop server-eval-args-left))' \
  "$JSON" \
  2>/dev/null || true

exit 0
```

Make it executable: `chmod +x ~/code/emacs-packages/claude-notify/bin/claude-notify-hook.sh`

**B. Add the following functions to `claude-notify.el`** (BEFORE the `(provide 'claude-notify)` line, AFTER the existing notification backend functions):

1. **`claude-notify--handle-hook (json-string)`**: The emacsclient entry point.
   - Guard: return early if `claude-notify-mode` is nil or `json-string` is nil/empty
   - Wrap body in `condition-case err` to catch all errors (log with `message`, never propagate)
   - Parse JSON with `(json-parse-string json-string :object-type 'alist)`
   - Extract: `notification_type`, `cwd`, `session_id`, `message`, `title` from the alist
   - Derive `project-name` from `cwd`: `(file-name-nondirectory (directory-file-name cwd))`
   - Call `(claude-notify--dispatch notification-type project-name session-id message title)`

2. **`claude-notify--dispatch (notification-type project-name session-id message title)`**: Route by notification type.
   - For Phase 1, handle `"permission_prompt"` only:
     - Call `(claude-notify--send)` with:
       - title: the `title` field from JSON (or "Claude Code" if nil)
       - subtitle: `project-name` (or "Unknown project" if nil)
       - body: the `message` field from JSON (or "Permission needed" if nil)
   - For other notification types: do nothing (Phase 3 will add more)
   - The function should use `pcase` on `notification-type` with a catch-all `_` case

IMPORTANT: The handler function is called from emacsclient context. It MUST NOT signal errors (would propagate to the shell script as a non-zero exit). The `condition-case` in `handle-hook` is the safety net.

IMPORTANT: Use `alist-get` with SYMBOL keys (e.g., `'notification_type`) because `json-parse-string` with `:object-type 'alist` returns symbol keys by default. Verify this matches the research examples.

  <action>
Add the `claude-notify-install-hook` interactive command to `claude-notify.el` (before the `provide` line).

The function MUST:

1. **Locate the hook script**: Use `(expand-file-name "bin/claude-notify-hook.sh" (file-name-directory (locate-library "claude-notify")))` to find the script. If `locate-library` returns nil (package not yet loaded via Doom), fall back to searching `load-path` or use `(file-name-directory (or load-file-name buffer-file-name))` as a compile-time fallback. Include a `user-error` if the script cannot be found.

2. **Determine the Emacs server socket path**: `(expand-file-name server-name server-socket-dir)`. Require `server` if not already loaded.

3. **Build the hook command string**: Format as `CLAUDE_NOTIFY_EMACS_SOCKET=<socket> <script-path>`. Use `shell-quote-argument` for both the socket path and script path.

4. **Read existing settings.json**:
   - Path: `(expand-file-name "~/.claude/settings.json")`
   - If file exists, parse with `(json-parse-string ... :object-type 'hash-table :null-object :null)` -- use hash-table for mutability
   - If file does not exist, create a new empty hash-table

5. **Merge the Notification hook entry**:
   - Get or create `hooks` key (hash-table)
   - Get or create `Notification` key within hooks (vector/array)
   - The new entry: `{"matcher": "permission_prompt", "hooks": [{"type": "command", "command": "<hook-command>", "timeout": 5}]}`
   - Check if a claude-notify entry already exists (match by command containing "claude-notify-hook.sh"). If found, UPDATE it in place. If not found, APPEND to the Notification array.
   - Use hash-tables and vectors to build the JSON structure (compatible with `json-serialize`)

6. **Write back settings.json**:
   - Create backup: `(copy-file settings-file (concat settings-file ".bak") t)`
   - Serialize with `json-serialize`
   - Pretty-print with `json-pretty-print-buffer` in temp buffer
   - Write to file
   - Message: "claude-notify: hook installed in ~/.claude/settings.json"

7. **Ensure script is executable**: `(set-file-modes script-path #o755)`

8. **Enable the mode**: Call `(claude-notify-mode 1)` after successful installation.

CRITICAL pitfall avoidance:
- The settings.json has existing PreToolUse, SessionStart hooks, plugins, env vars, model, statusLine -- ALL must be preserved. The hash-table approach ensures this: we only touch `hooks.Notification`, everything else passes through unchanged.
- Do NOT use alist for settings manipulation -- hash-table is required for `puthash` mutation and `json-serialize` compatibility.
- Create backup BEFORE writing.

After implementing, also add a helper `claude-notify--read-settings` and `claude-notify--write-settings` to keep `install-hook` clean. These helpers are used only here in Phase 1 but will be useful if we need to modify settings in later phases.

Finally:
- Byte-compile to verify no errors
- Git commit: `git add -A && git commit -m "feat: hook pipeline and settings.json installer"`
- Clean up .elc files
